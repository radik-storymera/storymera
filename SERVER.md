# Сервер, аккаунты и MySQL

## Что установлено

Локальный редактор и команда назначения администратора описаны в [ADMIN.md](ADMIN.md). Рабочий контент читается из MySQL.

Официальный ZIP MySQL Community 8.4.11 LTS находится в `.runtime/mysql-8.4.11-winx64`. Данные — `.local/mysql-data`. Это процесс пользователя, не служба Windows. Он слушает только `127.0.0.1:3307`, MySQL X Protocol отключён. Системные настройки и PATH не менялись. ZIP проверен по контрольной сумме, опубликованной на официальной странице: https://dev.mysql.com/downloads/mysql/8.4.html.

Созданы две независимые базы `jessica_stories` и `jessica_stories_test`, и пользователи `jessica_app` и `jessica_test` с правами только на свою базу. У них нет глобальных административных прав. Для миграций им разрешены CREATE/ALTER/INDEX/REFERENCES в своей базе; перед публичным запуском используйте отдельную миграционную учётную запись, оставив рабочему пользователю только SELECT/INSERT/UPDATE/DELETE.

Сгенерированный пароль root находится в `.local/mysql-root.txt`, параметры приложения — в `.env`. Не публикуйте эти файлы. `.runtime`, `.local`, `.env*` (кроме примера), сборки и логи исключены из Git. Vite запрещает выдачу серверных файлов и локальных каталогов. Секреты не используют префикс VITE_ и не импортируются клиентом.

Работайте из `C:\Projects\JessicaStories`. Сейчас MySQL, API и Vite уже запущены. После остановки запускайте в отдельных терминалах:


```powershell

```

```powershell

& 'C:\Program Files\nodejs\npm.cmd' run dev -- --port 5173 --strictPort
```

Сайт: http://localhost:5173; редактор: http://localhost:5173/admin. API: http://127.0.0.1:3001, браузер обращается к нему через `/api` и прокси Vite. MySQL в браузер не подключается. Остановка API/Vite — Ctrl+C; корректная остановка локального MySQL:


Не запускайте второй MySQL на том же каталоге. Если порт занят, проверьте свой уже запущенный процесс; не завершайте чужие процессы. Лог MySQL — `.local/mysql.log`.

## Новая среда / существующий MySQL

В этой рабочей папке `.env` уже заполнен. Не заменяйте его примером. На новой среде скопируйте `.env.example` в `.env` и локально задайте host, port, имена двух баз и пароли отдельных пользователей. Не отправляйте секреты в чат. APP_ORIGIN должен точно совпадать с адресом клиента. Для production требуется HTTPS и NODE_ENV=production (cookie Secure); этот этап не является публичным развёртыванием.

Администратор MySQL создаёт новые, ещё не существующие базы и пользователей (значения паролей подставляются локально):

```sql
CREATE DATABASE jessica_stories CHARACTER SET utf8mb4;
CREATE DATABASE jessica_stories_test CHARACTER SET utf8mb4;
CREATE USER 'jessica_app'@'localhost' IDENTIFIED BY '<local-generated-password>';
CREATE USER 'jessica_test'@'localhost' IDENTIFIED BY '<different-local-generated-password>';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,ALTER,INDEX,REFERENCES ON jessica_stories.* TO 'jessica_app'@'localhost';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,ALTER,INDEX,REFERENCES ON jessica_stories_test.* TO 'jessica_test'@'localhost';
```

Миграции: `npm.cmd run db:migrate` и `npm.cmd run db:migrate -- --test`. Версии SQL и контрольные суммы записываются в `schema_migrations`; применённые миграции не редактируйте. Добавляйте новые файлы. Использован MySQL2 + параметризованные запросы и версионированный SQL вместо ORM: схема небольшая, транзакционную защиту обновления обеспечивает атомарный UPDATE с ожидаемой версией. Миграции защищены advisory lock; MySQL DDL не обещает общую транзакцию для всего файла.

`server/setup-local.mjs` использовался один раз для создания случайных локальных секретов и init-file. Он отказывается перезаписывать готовую среду. Не запускайте повторную инициализацию существующего data-dir. Init-file после первого запуска удалён.

## API и безопасность

- POST `/api/auth/register`, POST `/api/auth/login`, POST `/api/auth/logout`, GET `/api/auth/me`.
- GET `/api/csrf` выдаёт подписанный токен для заголовка X-CSRF-Token; изменяющие запросы также требуют точный Origin. Токены разных вкладок не отменяют друг друга; после перезапуска API обновите страницу.
- POST `/api/reading/session` создаёт гостевую сессию; GET `/api/reading/state` выдаёт доступные истории; POST `/api/reading/open` начинает доступную главу; POST `/api/reading/unlock` транзакционно списывает ключики и навсегда открывает следующую платную главу; GET `/api/reading/chapter/:id` выдаёт только активную закреплённую ревизию; POST `/api/reading/advance` сохраняет сцену и завершённые сцены; POST `/api/reading/finish` подтверждает финал; POST `/api/reading/event` пишет разрешённые события продукта; POST `/api/reading/import` переносит допустимый старый гостевой путь. Все изменения требуют CSRF и Origin. Старый `/api/progress` возвращает 410.
- Сессия: случайные 32 байта, в БД только SHA-256 токена; HttpOnly, SameSite=Lax, Secure в production, срок 7 дней. Выход отзывает текущую серверную сессию. Токены входа не хранятся в localStorage.
- При регистрации пароль должен содержать 6–128 символов; существующие хеши не изменяются. Используется Argon2id (19 MiB, 2 прохода, 1 поток). Email нормализован trim/lowercase и уникален в БД. Логи запросов/паролей не ведутся. Ошибки API не раскрывают SQL или параметры соединения.
- Вход и регистрация ограничены 15 попытками за 15 минут на IP; хранилище лимитов в памяти одного процесса. Это нужно заменить общим хранилищем при масштабировании.
- Каждый запрос `/api/admin/*` проверяет серверную роль admin. Регистрация всегда создаёт reader. Роль назначается только локальной командой `npm.cmd run admin:grant -- 'email'`. Черновики и загрузка доступны только администратору; опубликованная глава выдаётся читателю только при активном прохождении.

## Прогресс

Сервер хранит гостевой путь и путь аккаунта в одной таблице `progress`, с отдельными владельцами. Гостевой токен случайный, в БД только SHA-256, HttpOnly cookie живёт 30 дней. Запись содержит ревизию, текущую и завершённые сцены, прежние совместимые поля пути и время Finish. Гость получает только главу `guest_free`; зарегистрированный пользователь открывает главы последовательно, а платная требует `chapter_unlocks`. Начатая версия закреплена даже после новой публикации или перестановки глав.

Завершение идемпотентно: повтор запроса не меняет результат. Перед подтверждением сервер проверяет финальную сцену. Стоимость хранится в `chapters.key_cost`; ноль означает бесплатную главу. `/api/reading/unlock` блокирует строку пользователя, проверяет баланс, создаёт уникальное постоянное открытие и списывает стоимость одной транзакцией. Повторное открытие не списывает ключики. Начисление и настоящая оплата пока отсутствуют.

Сервер выдаёт и воспроизводит неизменяемый граф закреплённой ревизии без фильтра по ID или прежнему `kind` сцены. Сцена `demo` теперь показывается и ждёт своё сохранённое действие, как остальные сцены. Сохранение на ней восстанавливается на ней же; ранее продвинувшихся до `tomorrow` система назад не перемещает. Draft preview получает сохранённый черновой граф без записи прогресса. Рабочие версии и черновик не публикуются и не переписываются; миграция данных не нужна. Подписочные баннеры и отдельный режим продолжения не создаются интерфейсом, но исторический авторский текст старых версий остаётся в документах.

При регистрации гостевой прогресс и `poll_progress` транзакционно копируются в новый аккаунт. Уникальные ключи делают перенос идемпотентным; более новый путь аккаунта не перезаписывается. Гостевой путь браузера остаётся на месте и снова используется после выхода. При входе в существующий аккаунт гостевой путь не смешивается с ним. Старое локальное сохранение Jessica импортируется только для гостевой бесплатной главы, когда серверного пути ещё нет.

BroadcastChannel уведомляет вкладки о входе и выходе. Без поддержки канала вкладка сверится с сервером после обновления страницы; серверная проверка владельца и версии остаётся обязательной.

## Сборка, тесты, резервные копии

```powershell
& 'C:\Program Files\nodejs\npm.cmd' run build
& 'C:\Program Files\nodejs\npm.cmd' run build:server
& 'C:\Program Files\nodejs\npm.cmd' test
& 'C:\Program Files\nodejs\npm.cmd' run test:api
& 'C:\Program Files\nodejs\npm.cmd' run test:reading
& 'C:\Program Files\nodejs\npm.cmd' run test:admin
& 'C:\Program Files\nodejs\npm.cmd' run test:secrets
& 'C:\Program Files\nodejs\npm.cmd' run db:backup
& 'C:\Program Files\nodejs\npm.cmd' run db:verify-backup
```

Серверную сборку можно запустить `& 'C:\Program Files\nodejs\node.exe' server-dist/server/index.js` из корня проекта. Она использует тот же локальный `.env`.

API-тесты используют исключительно TEST_DB_NAME с суффиксом `_test`, отличным от DB_NAME, и отдельные права пользователя. Они удаляют только созданные тестовые записи, не очищают базы/таблицы. Для ручной изолированной проверки есть `tests/serve.ts` (порт 3002); клиент на 5175 запускается с временной переменной текущего процесса JESSICA_API_PORT=3002.

Перед изменением схемы остановите активное редактирование и выполните `db:verify-backup`. Он создаёт дамп в `.local/backups`, восстанавливает его в отдельную временную БД и сравнивает таблицы; после успешной проверки временная база удаляется. Рабочая БД не перезаписывается. Пароль не передаётся в командной строке. Дамп содержит данные пользователей. SQL-дамп не включает загруженные файлы: сохраняйте вместе с ним `.local/media`. Не копируйте работающий MySQL data-dir вместо дампа.

## До публичного запуска

Не реализованы подтверждение email, восстановление пароля, почтовый сервис, начисление ключиков и оплата. Пункт усиленной защиты регистрации и голосований (CAPTCHA, IP/устройства, почтовые лимиты и анализ подозрительной активности) намеренно отложен. Управляемые медиа проверяют права главы, но исторические файлы `public/media` статичны и уже скачанные материалы нельзя отозвать. Нужны HTTPS, reverse proxy, политика персональных данных, очистка сессий, аудит безопасности и тесты на физических телефонах. Публичная публикация не выполнялась.
