Не меняй утверждённый дизайн читательской части, сюжет, видеоуправление, аккаунты, права и существующие ID. Не публикуй сайт в интернете и не публикуй рабочие черновики владельца. Тестируй на отдельной БД и тестовых медиа. Сохраняй несохранённые правки и защиту от конфликтов вкладок. Если нужны миграции, сначала выполни резервное копирование и проверку восстановления по процедуре проекта. Не удаляй рабочие файлы ради демонстрации массового удаления.

Эти результаты — ручные наблюдения владельца, не независимый аудит кода, безопасности или всех браузеров.

## 01. Автоматический ID истории

Убрать обязательное поле «Постоянный идентификационный номер» из создания истории. Генерировать уникальный постоянный ID автоматически, как уже сделано для сцен. Переименование не меняет ID. Существующие значения, включая числовые, не преобразовывать. При необходимости ID доступен для копирования в технических сведениях. Две истории с одинаковым названием должны получать разные ID.

## 02. Статус истории без необъяснённых чисел

Сейчас видна строка «Только черновик · 2». По совпадению с формой число предположительно является ID; проверить источник. Убрать технический ID из основного списка. Показывать отдельно подписанный статус и количество глав, например «Не опубликована · Глав: 1». Не называть неопубликованную историю опубликованной из-за одного сохранения. Учесть историю с опубликованными главами и новым черновиком; использовать реальные условия текущей модели.

## 03. Однозначные действия и язык

Кнопка перехода к главам должна обозначать действие: «Перейти к главам» / “View chapters”, а не «Открытые главы». Часть русских надписей на скриншотах могла появиться из-за перевода браузера. Проверять исходный интерфейс с отключённым переводом. Не добавлять новую систему локализации без необходимости; сохранять текущий язык интерфейса и не переводить авторские тексты. Если русская локализация уже существует, привести её подписи в порядок.

## 04. Кириллица в именах файлов

В выборе портрета имя файла отображается искажёнными символами. Воспроизвести загрузкой тестового файла с кириллицей, пробелами и цифрами. Проверить загрузку, метаданные, БД, API и отображение. Хранить безопасное служебное имя отдельно от читаемого исходного. Не применять повторное перекодирование к корректным именам. Не угадывать невосстановимые старые имена и не менять ссылки на файлы. Исправить причину; о старых повреждённых данных сообщить отдельно.

## 05. Описание изображения

Поле “Accessible description” объяснить как альтернативный текст для пользователей программ чтения с экрана. В русской локализации: «Описание изображения для незрячих пользователей». Добавить краткую подсказку и пример, например «Джессика с чемоданом на городской улице». Не путать с текстом истории и не использовать имя файла как содержательное описание.

## 06. Объяснение публикации истории

Проверено: история появилась после публикации первой главы. После сохранения новой истории показывать следующий шаг: «История сохранена. Добавьте и опубликуйте первую главу, чтобы она появилась в каталоге», с переходом к главам. Не создавать отдельный противоречащий существующей модели механизм публикации истории. Публикация всей главы остаётся явной операцией.

## 07. Миниатюры без потери содержания

В списке сцен портреты сильно обрезаны. Показывать полный кадр в ограниченном размере миниатюры (contain и спокойный фон), без растяжения. Для видео показывать обложку и отметку типа. Применить согласованное поведение в медиатеке. Не менять кадрирование утверждённой читательской главной страницы.

## 08. Предпросмотр как читательский проигрыватель

Сейчас предпросмотр на ПК размещает фото по центру, текст длинной строкой снизу. Использовать общий с читательским интерфейсом компонент и стили: на ПК медиа слева, текст и действия справа; на телефоне медиа, затем текст и действия. Сохранить размеры, рамку, переходы и управление видео.

Над проигрывателем компактная полоса «Предпросмотр черновика · Прогресс не сохраняется», действия «Вернуться к сценам» и «Начать заново». Сохранять состояние редактора при возврате. Предпросмотр не меняет читательский прогресс, не публикует главу и остаётся доступен только администратору. Не переносить доступ к черновикам в публичные API ради повторного использования UI. Проверить прохождение обеих веток и видео.

## 09. Структура шапки редактора

Разделить название сцены и статус сохранения. Показывать «Есть несохранённые изменения», «Сохранение…», «Сохранено» или понятную ошибку. Значения draft 4 / edit version 1 / постоянный ID перенести в раскрываемые технические сведения с объяснением фактического смысла по коду. Не называть техническую ревизию номером главы или сцены.

## 10. Порядок списка и сюжетные связи

Editor order переименовать в «Порядок в списке» / “List order”. Подсказка: «Влияет только на расположение в редакторе. Переходы читателя настраиваются в разделе “Действия”». Проверить, что связи хранятся по ID, а не по Order.

При одинаковом значении порядок должен быть стабильным после перезагрузки. Предусмотреть удобные кнопки «Выше / Ниже», чтобы владельцу не требовалось считать номера вручную. Любая перенумерация касается лишь чернового порядка отображения и не меняет переходы, опубликованные версии и прогресс. Две сцены с одинаковым Order не должны автоматически становиться вариантами предыдущей сцены.

## 11. Конец главы

Флажок назвать «Завершает главу» / “Ends chapter”, добавить объяснение: это завершение выбранного пути; в главе могут быть разные финалы. Начальная сцена может одновременно быть финальной.

Финал и обычные переходы внутри главы не должны противоречить друг другу. При включении флажка у сцены с действиями объяснить конфликт и предложить явное решение, не удалять действия молча. Серверная проверка также должна обнаруживать несовместимое состояние. Сохранить корректный финальный экран читателя.

## 12. Условные фрагменты текста

Под действиями есть техническая надпись “Imported conditional paragraphs remains tied to existing choices”. Исследовать, какие условия и фрагменты существуют и как привязаны к ID действий. Вместо общей непонятной надписи показать в сцене понятный раздел: условие выбора и соответствующий текст. Для первой версии достаточно просмотра существующих условий с ясным объяснением ограничений редактирования; новый конструктор условий не требуется.

Не терять эти фрагменты при обычном сохранении. При изменении или удалении связанного действия не оставлять скрытые нерабочие условия: блокировать с объяснением либо запрашивать осознанное исправление. Переименование подписи кнопки не должно ломать связь. Проверить оба пути до общей сцены. Если зависимостей нет, не показывать предупреждение.

## 13. Начальная сцена и ошибки публикации

При создании первой сцены назначать её начальной, если начало не задано. Назначение должно сохраняться вместе с черновиком. Не заменять существующую корректную начальную сцену при добавлении следующих.

В свойствах главы оставить явный выбор начала. Если начало отсутствует или неверно, показывать основную ошибку с переходом к полю; не засорять список производными сообщениями о недостижимости всех сцен и финала. После исправления начала выполнять полную проверку графа. Не скрывать независимые ошибки. Проверить односценную главу и разветвлённую главу.

## 14. Автоматическая обложка видео

Сейчас публикация требует poster; вручную назначенная картинка решает проблему. После выбора нового ролика автоматически извлекать его первый доступный декодируемый кадр, сохранять как управляемое изображение и назначать обложкой. Не заменять уже выбранную пользователем обложку без его действия.

Показать подготовку, готовую обложку и возможность ручной замены. При ошибке сразу объяснить необходимость загрузить картинку вручную; не держать форму бесконечно заблокированной. Обложка используется в редакторе, предпросмотре и миниатюрах медиатеки; у ролика не должно быть “No image”, когда есть доступная обложка. Определить согласованно обложку медиа по умолчанию и возможное переопределение в сцене.

Использовать доступные инструменты или браузерные возможности. Не устанавливать системные программы/службы без согласования. Сохранить приватность черновых файлов, серверную валидацию изображения и ручной запуск видео. Обязательность обложки обозначить рядом с полем до попытки публикации.

## 15. Фильтры медиатеки

Вкладки «Все / Изображения / Видео» с реальным количеством файлов. Определять тип по проверенным метаданным, а не только расширению. Показать понятное пустое состояние. Фильтры не меняют доступность файлов и не удаляют их.

## 16. Массовый выбор и безопасное удаление

Чекбокс у файла, «Выбрать все показанные», число выбранных и «Удалить выбранные». На смене вкладки/страницы фильтра сбрасывать выбор: скрытые файлы не должны неожиданно удаляться. Перед операцией подтверждение с количеством и составом выбранного.

Сервер проверяет роль, CSRF и все ссылки на каждый файл: портреты, черновики, опубликованные и старые версии, обложки видео и другие зависимости модели. Используемый файл удалять нельзя; показать понятные места использования. Проверять зависимости непосредственно при удалении и защитить от гонки с сохранением/публикацией. Не доверять только клиентскому состоянию.

В смешанном наборе заранее показать, какие файлы защищены, а какие можно удалить; подтверждать именно допустимый набор. Отчёт по каждому файлу: удалён, заблокирован или ошибка. Не сообщать успех при неудачной операции. Предпочтительно реализовать восстановимую корзину вне публичной раздачи; автоматическое окончательное удаление в рамках этапа не требуется. Описать восстановление. Не удалять оригиналы на E: или файлы вне управляемого хранилища.

## 17. Пакетная загрузка изображений

Разрешить выбрать несколько изображений одним действием. Показать очередь, состояние/прогресс каждого файла, успех либо понятную ошибку и повтор только неудачных загрузок. Не отменять успешные файлы из-за ошибки соседнего. Ограничить параллелизм и документировать предел размера и количества; не читать все крупные файлы одновременно в память. Сохранить действующие серверные ограничения и проверку форматов. Повтор не должен незаметно дублировать уже успешные элементы. Пакетная загрузка видео не обязательна на этом этапе.

## Приёмка и порядок выполнения

1. Проверить модель статусов, Order, условных фрагментов и метаданных файлов. Зафиксировать реальные причины до исправлений.
2. Выполнить правки форм, пояснений и автоматических ID/начала.
3. Унифицировать предпросмотр с читательским компонентом.
4. Доработать обложки и медиатеку.
5. Выполнить сборки клиента/сервера и целевые проверки ниже. Тестовые публикации — только в тестовой БД.

### Обязательные сценарии

- Создание истории без ручного ID, повтор названия, переименование без изменения связей.
- Новая глава: первая сцена автоматически начальная; она же финальная; публикация выводит историю в тестовый каталог.
- Две ветки сходятся; сцены с одинаковым Order корректно проходят; перестановка списка не меняет сюжет.
- Предпросмотр соответствует читательской версии на ПК и телефоне, не пишет прогресс и не раскрывает черновик гостю.
- Переходы редактора 1 → 2, 3 → 2, 2 → 1 → 2; сохранение текста; конфликт вкладок и ошибка сети без потери правок.
- Новый ролик получает poster; ручная замена сохраняется; ошибка извлечения имеет ручной выход; публикация с валидной обложкой проходит.
- Кириллическое имя корректно после загрузки и повторного открытия.
- Пакет: несколько успешных картинок и один некорректный файл; успехи сохранены, повторяется только ошибка.
- Фильтры, сброс выбора, удаление неиспользуемых тестовых файлов, отказ для используемых (включая старые версии и poster), отсутствие доступа читателя к удалению. Проверить восстановление из корзины, если она реализована.
- ПК при масштабе 100%: 1366×768 и 1440×900; мобильная ширина 390 px. Эмуляцию не выдавать за проверку физического телефона.
