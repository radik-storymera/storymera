# Storymera — локальный прототип с редактором

Локальный прототип интерактивных историй: React + TypeScript + Vite, Express + TypeScript, MySQL 8.4 LTS. Интерфейс на английском. Гость видит Jessica и читает настроенную бесплатную главу без регистрации; полный каталог и ключики появляются после регистрации. Запуск сервера — [SERVER.md](SERVER.md), работа с контентом — [ADMIN.md](ADMIN.md), модель доступа — [ACCESS.md](ACCESS.md).

Подготовка первого production-развёртывания через Docker Compose описана в [DEPLOYMENT.md](DEPLOYMENT.md). Она использует отдельные контейнеры и тома и не переиспользует локальный Windows data-dir MySQL.

## Клиент в PowerShell (сначала запустите MySQL и API по SERVER.md)

```powershell
Set-Location C:\Projects\JessicaStories
& 'C:\Program Files\nodejs\npm.cmd' install --cache .npm-cache --engine-strict
& 'C:\Program Files\nodejs\npm.cmd' run dev -- --port 5173 --strictPort
```

Откройте http://localhost:5173. Сервер привязан только к localhost. Для остановки в терминале нажмите Ctrl+C. Node.js 24.19.0 совместим с Vite 7; менять политику PowerShell не нужно.

Публичная главная получает счётчики опубликованных глав, иллюстрированных сцен и активных опубликованных опросов из `/api/content/home`. Страницы `/about`, `/how-it-works`, `/privacy` и `/terms` доступны без входа. Ссылка `/contact` появляется только после задания настоящего адреса `CONTACT_EMAIL` в локальном `.env`; пустое значение не публикует вымышленный способ связи. Перед публичным размещением замените локальный домен в `index.html`, `public/robots.txt` и `public/sitemap.xml` на фактический HTTPS-домен.

```powershell
& 'C:\Program Files\nodejs\npm.cmd' test
& 'C:\Program Files\nodejs\npm.cmd' run build
& 'C:\Program Files\nodejs\npm.cmd' run build:server
```

Сборки проверяют клиент и сервер. Открывайте работающий прототип через Vite на `http://localhost:5173`: он направляет `/api` в локальный Express. Для самостоятельного запуска собранного клиента потребуется настроить прокси `/api`; публичное развёртывание на этом этапе не выполняется. Все зависимости — локальные зависимости проекта. Внешние шрифты, аналитика и сетевые сервисы не подключены.

## История и голосования

Текущий порядок чтения линейный: каждая сцена ведёт к следующей по порядку. Внутренние опросы не меняют маршрут; финальное голосование доступно после завершения главы. Редактор и правила голосования описаны в [POLLING.md](POLLING.md). Следующие строки о `actions`, `variants` и графе описывают совместимость со старыми опубликованными версиями, а не текущий редактор.

- Опубликованные главы и черновики находятся в MySQL. Для редактирования используйте `/admin`, инструкция в [ADMIN.md](ADMIN.md). `src/story-model.ts` содержит общие типы, `src/linear.ts` — порядок сцен, `src/story.ts` — загрузку опубликованных версий. Замороженный первоначальный импорт — `server/legacy-story.ts`.
- Текущая опубликованная первая глава содержит девять сцен: `arrival` → `crossroads` → `cafe` → `river` → `square` → `poll-after-square` → `demo` → `evening` → `tomorrow`. Опрос №1 занимает отдельную сцену после `square` и не меняет маршрут. Прежняя служебная сцена `demo` остаётся обычной сюжетной сценой.
- `actions`, `choice` и `variants` сохраняются только в исторических версиях и декодере прежнего прогресса. Старые сохранения остаются на закреплённой ревизии и не перемещаются назад. Тексты и медиа владельца не переписаны; если старый текст сцены упоминает подписку, его можно заменить в отдельном черновике и опубликовать.
- Новая публикация создаёт новую ревизию; старые сохранения продолжают свою версию.

## Замена медиа

В `public/media` сохранены прежние локальные заглушки и изображения Jessica. Исторические соответствия — [MEDIA.md](MEDIA.md). Новые медиа загружаются через `/admin` в управляемую папку `.local/media`, затем выбираются в карточке или сцене. Код истории редактировать больше не требуется. Структура медиа:

```ts
media: { type: 'image', src: '/media/jessica-arrival.webp', alt: 'Jessica arriving in her new city' }
// Или:
media: { type: 'video', src: '/media/arrival.mp4', poster: '/media/arrival-poster.webp', alt: 'Jessica arriving in her new city' }
```

Необязательное поле `caption` задаёт подпись. В проигрывателе `object-fit: contain` сохраняет изображение целиком; карточка допускает аккуратное кадрирование портрета. Видео использует Play/Pause/Replay и Sound on/off, playsInline, muted и preload=metadata; autoplay отсутствует. Компонент src/SceneVideo.tsx синхронизирует кнопки с событиями видео и останавливает его при размонтировании. Рамка 9:16, видео другого формата сохраняет полный кадр через contain. Поле poster задаёт первый кадр отдельно и позволяет открыть сцену без ожидания загрузки ролика. При ошибке запуска появляется сообщение. Тестовый ролик находится в финальной сцене tomorrow. Подробности — VIDEO.md.

## Последовательное чтение и демонстрационные функции

Гость начинает без регистрации: сервер создаёт анонимную сессию и хранит текущую сцену, завершённые сцены, статусы опросов и закреплённую ревизию в MySQL. Браузер сохраняет только HttpOnly cookie. После **Finish chapter** гость видит превью продолжения и других историй. Следующая глава открывается зарегистрированным пользователем за заданное в админке число ключиков; стоимость `0` означает бесплатный доступ.

Для аккаунта сохранение привязано к пользователю. При регистрации гостевой путь и пропуски опросов идемпотентно копируются в аккаунт без отката; гостевой путь браузера остаётся отдельным и снова используется после выхода. Уже начатая ревизия и существующие записи прогресса не сбрасываются. Запросы чтения проверяются сервером; устаревшая вкладка получает конфликт. Подробности — [SERVER.md](SERVER.md).

Управляемые медиа `/api/media/:id` проверяют гостевой доступ, бесплатность или постоянное открытие главы. Исторические файлы в `public/media` остаются статическими, а уже скачанные материалы нельзя отозвать; перед публичным запуском их нужно перенести в управляемое хранилище.

Регистрация и вход реализованы локально, пароли хешируются Argon2id. Сервер хранит реальный баланс ключиков и постоянные открытия глав, но начисление, тарифы и настоящая оплата не реализованы. Нет отправки писем, подтверждения email, восстановления пароля и настоящих подписок. После финальной сцены читатель подтверждает Finish chapter.

## Проверки

`tests/progress.test.ts` проверяет линейный порядок и старый формат сохранения; `tests/reading.test.ts` — последовательное чтение и завершение; `tests/linear-polls.test.ts` — голосование, права, закрытие и статистику на отдельной тестовой БД. Запустите `npm.cmd run test:polls`. Браузерные результаты раннего этапа записаны в `VERIFICATION.md`.

## Основные файлы

`src/main.tsx` — каталог и проигрыватель; `src/useReader.ts` — действия чтения; `src/Admin.tsx` — редактор; `src/story-model.ts` и `src/progress.ts` — модель графа и проверка пути; `server/reading.ts` — последовательный доступ и сохранение; `server/admin.ts` — API админа и медиа; `server/content.ts` — версии; `migrations/` — SQL-схема; `.local/media/` и `public/media/` — медиа; `tests/reading.test.ts` — серверные регрессии; `package.json` — команды.
