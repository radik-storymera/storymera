# Локальное управление контентом

Откройте `http://localhost:5173/admin/stories` после запуска MySQL, API и Vite по [SERVER.md](SERVER.md). Интерфейс на английском, адрес доступен только на этом компьютере. Это публикация версии истории в локальном каталоге, а не публикация сайта в интернете. Старый адрес `/admin` открывает список историй.

## Пользователи

Раздел `/admin/users` показывает серверную статистику регистраций, постраничный список из 20 аккаунтов и поиск по части email без учёта регистра. Администраторы видны в списке с ролью, но исключены из продуктовых счётчиков читателей. Дата последнего входа пока не собирается и отображается как недоступная.

Карточка `/admin/users/:id` показывает прогресс, навсегда открытые главы и журнал ключиков без хешей паролей, сессий или cookies. Начисление, списание и установка баланса выполняются транзакционно вместе с записью в `key_transactions`; UUID запроса защищает от повторного применения одной операции. Новые открытия платных глав также записываются в журнал как `chapter_unlock`. Старые изменения баланса не восстанавливаются вымышленными записями.

Сброс прогресса удаляет только строки выбранного пользователя из `progress`. Баланс, журнал ключиков, `chapter_unlocks`, `poll_progress` и `poll_votes` сохраняются.

## Доступ

Зарегистрируйте обычный аккаунт через сайт. По умолчанию регистрация всегда назначает роль reader. Владелец проекта вводит email выбранного уже существующего аккаунта только в своём терминале PowerShell:

```powershell
Set-Location C:\Projects\JessicaStories
& 'C:\Program Files\nodejs\npm.cmd' run admin:grant -- 'email-владельца@example.com'
```

Пароль для команды не нужен. После назначения обновите страницу `/admin` либо войдите снова. Не присылайте пароль в чат. Другим людям доступ не назначается автоматически. Сессии и CSRF защищают административные запросы; сервер проверяет роль при каждом запросе, включая загрузку файлов, выдачу чернового медиа и предпросмотр.

## Экраны и работа с черновиком

| Экран | Локальный адрес |
| --- | --- |
| Все истории | `/admin/stories` |
| Создание истории | `/admin/stories/new` |
| Свойства истории | `/admin/stories/<heroine-id>/edit` |
| Главы истории | `/admin/stories/<heroine-id>/chapters` |
| Создание главы | `/admin/stories/<heroine-id>/chapters/new` |
| Свойства главы | `/admin/stories/<heroine-id>/chapters/<chapter-id>/edit` |
| Сцены главы | `/admin/stories/<heroine-id>/chapters/<chapter-id>/scenes` |
| Редактор сцены | `/admin/stories/<heroine-id>/chapters/<chapter-id>/scenes/<scene-id>/edit` |
| Медиатека | `/admin/media` |
| Список голосований | `/admin/polls` |
| Создание голосования | `/admin/polls/new` |
| Редактор голосования | `/admin/polls/<poll-id>/edit` |
| Статистика | `/admin/polls/<poll-id>/stats` |

Сцены теперь читаются строго в порядке списка. Кнопки Up/Down в списке сцен меняют порядок чтения. Создайте отдельную сцену типа Poll и выберите для неё внутренний опрос; обычная Story-сцена опрос не содержит. Свойства главы задают финальный опрос типа Canonical. Старые сюжетные действия и условия больше не управляют переходами. Правила голосования и миграции: [POLLING.md](POLLING.md).

1. На экране Stories откройте главы существующей героини либо нажмите Add story. Для новой героини задайте имя, описание и портрет; постоянный уникальный ID создаётся автоматически и не меняется при переименовании. Сущность БД остаётся heroine. Список показывает статус публикации, наличие черновика и количество глав. После сохранения истории добавьте и опубликуйте первую главу, чтобы она появилась в каталоге.
2. В Chapters видно порядок, опубликованную версию и наличие черновика. Add chapter создаёт отдельный черновик по названию: постоянный ID создаётся автоматически, первая глава получает порядок 0, каждая следующая добавляется в конец. Кнопки Up/Down переставляют главы в каталоге, не меняя их ID, версий и содержимого. Открытие опубликованной главы создаёт следующую черновую версию, не меняя опубликованную.
3. В свойствах главы задаются название, подзаголовок, описание, финальное голосование, стоимость в ключиках и Guest free chapter. Стоимость `0` означает бесплатную главу. Гостевой может быть только одна глава: сохранение новой отметки снимает предыдущую. Постоянный ID главы доступен только для просмотра и копирования в Technical details; переименование его не меняет. Первая созданная сцена становится начальной автоматически. На экране Scenes введите название в New scene title и нажмите Add scene. Уникальный ID сцены создаётся автоматически и остаётся неизменным при переименовании; он доступен в раскрываемом блоке редактора. List order и кнопки Up/Down задают порядок чтения.
4. Редактор сцены содержит текст, медиа, превью, постер видео, альтернативное описание для программ чтения с экрана и выбор внутреннего опроса. Файл можно выбрать из медиатеки или загрузить прямо в редакторе. Для нового видео браузер пытается извлечь первый декодируемый кадр и загрузить его как постер; при неудаче выберите изображение вручную. Поставленная вручную обложка сцены имеет приоритет над постером видео по умолчанию. Save остаётся на экране; Save and return сохраняет весь черновик главы и возвращает к списку. Back to scenes оставляет несохранённые правки в памяти вкладки.
5. На экране Scenes кнопка Check chapter показывает ошибки структуры. Preview открывает сохранённый черновик в общем с читательской частью проигрывателе без изменения прогресса аккаунта. Публикация доступна только для сохранённого черновика, требует отдельного подтверждения и выполняет серверную проверку, включая медиа. Публикуется глава целиком, отдельной публикации сцен нет.

Сцена Jessica с постоянным ID `demo` редактируется и воспроизводится на общих основаниях, несмотря на прежнее значение `kind`. Draft preview показывает её сохранённые название, текст, медиа и действия; переходы задаются целевыми ID действий. В текущем черновике и опубликованной версии после `square` следует `demo`, затем `evening` и `tomorrow`. Черновик владельца автоматически не переписывается и не публикуется.

Переход между сценами той же главы сохраняет изменения в памяти вкладки. При уходе к другой истории, главе или медиатеке с несохранёнными правками предлагается Save and continue либо Cancel. При обновлении или закрытии страницы браузер показывает стандартное предупреждение; перед обновлением сохраните черновик вручную. При ошибке сохранения экран и текст остаются на месте. При конфликте двух вкладок сервер отклоняет устаревшую версию; не заменяйте другой черновик вслепую. Адреса поддерживают обновление страницы и историю браузера. Для неверной принадлежности главы или сцены появляется ошибка с возвратом к списку.

Проверка публикации требует начальную сцену, обязательные медиа и постеры, непустые подписи кнопок, существующие цели только этой главы, достижимость каждой сцены, достижимый финал и отсутствие циклов. Незавершённая сцена должна иметь действия. Для опубликованных глав доступно Archive/Restore: архив скрывает главу из каталога, а версии и прогресс сохраняются.

## Файлы и версии

JPEG, PNG, WebP, MP4 и WebM попадают в `.local/media` с случайными безопасными именами. В MySQL остаются метаданные, ссылки и связи с версиями. Загружайте файлы только через форму; пути к другим папкам компьютера API не принимает. Сервер потоково записывает видео, проверяет тип содержимого и лимит размера. По умолчанию изображения до 12 МБ, видео до 200 МБ; их можно настроить `MEDIA_IMAGE_MB` и `MEDIA_VIDEO_MB` в `.env` перед запуском API. При чтении ролика поддерживаются Range-запросы.

Черновые файлы доступны только администратору; после публикации управляемые файлы доступны гостю только для Guest free chapter, а аккаунту — для бесплатной или навсегда открытой главы. Один файл может использоваться в нескольких сценах. В медиатеке доступны фильтры по проверенному сервером типу, выделение показанных файлов и пакетная загрузка до 10 изображений за выбор, не более двух одновременных запросов. Очередь показывает результат каждого файла; Retry failed повторяет только неудачный файл. Лимиты размера действуют для каждого файла отдельно. Видео загружается по одному. Исходное имя, включая кириллицу, хранится отдельно от случайного служебного имени; старые уже искажённые имена автоматически не угадываются и не исправляются.

Удаление начинается с проверки выбранных файлов. Сервер повторно проверяет зависимости при удалении: портреты, все версии глав (включая черновые, опубликованные и старые), постеры видео и файлы в корзине. Используемые файлы остаются на месте и показываются как защищённые. Допустимые файлы перемещаются в `.local/media-trash`, недоступную по публичному маршруту. Раздел Recoverable trash восстанавливает файл с прежним ID. Автоматического окончательного удаления нет. Старые файлы в `public/media` сохранены как исторические материалы первой главы и не входят в эту операцию.

Опубликованные версии неизменяемы. Начатое прохождение связано с номером версии и сохраняется после новой публикации или изменения порядка глав. В списке главы показаны читательский номер, статус публикации и наличие черновика; технические номера ревизий раскрываются отдельно. Читатель явно подтверждает Finish chapter на финальной сцене; следующая опубликованная глава требует постоянного открытия за настроенную стоимость, если она больше нуля. В читательском интерфейсе нет сброса главы. Старые версии, на которые ссылаются сохранения, не удаляются.

## Резервное копирование

Перед изменением схемы используйте `npm.cmd run db:verify-backup`: он создаёт дамп в `.local/backups`, восстанавливает его в отдельную временную БД и сравнивает таблицы. После успешной проверки временная база удаляется; при ошибке она остаётся для диагностики. Рабочая БД не перезаписывается. Дамп содержит пользовательские данные — храните его локально и защищайте как основную БД. `npm.cmd run db:backup` создаёт обычный дамп без проверки восстановления. В дамп БД не входят файлы `.local/media` и `.local/media-trash`: копируйте обе папки вместе с дампом для полного восстановления проекта. Не размещайте `.local` или `.env` в публичных каталогах.

Этот этап не реализует подписку, начисление ключиков или оплату. Управляемые медиа проверяют доступ главы, но прежние статические файлы `public/media` остаются локально доступны по URL. Перед публичным размещением нужны HTTPS, перенос платных файлов в управляемое хранилище, отдельные права для миграций, проверенный процесс восстановления, аудит безопасности и эксплуатационные настройки.
