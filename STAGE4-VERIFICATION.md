# Этап 4 — проверка локального редактора

## Резервная копия и миграция

До изменения рабочей схемы команда `node server/verify-backup.mjs` создала дамп в `.local/backups` и восстановила его в отдельно созданную временную базу. Хеши содержимого всех четырёх таблиц совпали. Рабочая база не перезаписывалась; дамп оставлен в локальном защищённом каталоге. Временная база удалена после проверки. Секреты и содержимое дампа в отчёт не включены.

Затем применены `002_content.sql` и `003_progress_version.sql`. Однократный импорт исходной Jessica в опубликованную ревизию 1 сохраняет `jessica/first-day` и все постоянные ID сцен. Проверка показала одну опубликованную первую ревизию и ноль строк прогресса без связанной версии. Повторный импорт использует `INSERT IGNORE` и не переписывает существующие записи. После миграции создан второй дамп новой схемы и проверено его восстановление: девять таблиц совпали, временная база удалена. Основная БД оставалась отдельной от тестовой.

## Автоматические проверки

- `npm.cmd run build` и `npm.cmd run build:server` — успешны.
- `npm.cmd test` — 4/4 проверки истории и прогресса.
- `npm.cmd run test:api` — 2/2 сценария регистрации, сессий, CSRF, конфликтов прогресса и ошибки БД. Токен, полученный другой вкладкой, теперь не отменяет предыдущий.
- `npm.cmd run test:admin` — 1 комплексный сценарий с отдельной базой: guest/reader 401/403, роль регистрации reader даже при присланном `role=admin`, загрузка настоящего JPEG, MP4 и постера; отклонение ложного JPEG; закрытые черновые медиа; сохранение/reopen двух веток с финалом; preview без записи прогресса; публикация только после прохождения валидации; глава в каталоге; старое прохождение после второй публикации, reset в новую версию; 409 при устаревшей правке; 206 Range на опубликованном MP4. Генерируемые тестовые записи и файлы удалены по точным ID после сценария.
- `npm.cmd run test:secrets` — реальные сгенерированные пароли БД не оказались в собранных клиентских файлах; значения не выводились.
- На живом основном localhost: сайт, `/admin`, каталог и первая глава отдали 200; `.env` и `.local/mysql-root.txt` — 403; `/api/admin/heroines` без входа — 401.

## Браузер

На временных портах 5175/3002 и отдельной тестовой БД зарегистрирован тестовый читатель; роль ему назначена только локальной SQL-командой в тестовой базе. В `/admin` загружено изображение, создана глава с конечной сценой, заполнены поля, сохранён и повторно открыт черновик. Предпросмотр показал загруженное изображение, не имел горизонтального переполнения. После явного подтверждения версия появилась в каталоге рядом с прежней главой. На ширине 390 px редактор открыл сцену и поля без горизонтального переполнения. Две вкладки открыли один черновик: первая сохранила правку, а вторая получила конфликт, сохранив несохранённый текст. Во время проверки выявлено и исправлено взаимное аннулирование CSRF-токенов разных вкладок; повторная проверка сохранения прошла. Браузерный тестовый аккаунт, глава и медиа удалены из тестовой БД и управляемой папки по точным ID; временные API и Vite остановлены.

## Ограничения проверки

Не проверены реальная пользовательская учётная запись администратора в основной БД (владелец ещё не указал email), другие физические браузеры и телефоны, крупная загрузка на лимите 200 МБ, все варианты кодеков и полное восстановление набора «дамп БД + каталог медиа». Восстановление именно SQL-дампа в отдельную БД проверено до миграции. Это локальный прототип, не публичное развёртывание и не защита будущего платного контента.
